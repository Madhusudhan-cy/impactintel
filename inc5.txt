# 2. Authentication Architecture — GitHub OAuth App

Use GitHub OAuth App authentication rather than GitHub App installation.

### Expected authentication flow

1. User opens the application.
2. User clicks Continue with GitHub.
3. Frontend redirects to the backend's GitHub OAuth authorization endpoint.
4. Backend redirects the user to GitHub.
5. User authorizes the requested permissions.
6. GitHub redirects to the backend OAuth callback.
7. Backend validates OAuth state and exchanges the authorization code for an access token.
8. Backend securely stores or manages the access token.
9. Backend retrieves the GitHub user profile.
10. Backend establishes a secure application session.
11. Frontend redirects the user to repository selection.
12. Backend retrieves repositories accessible through the user's authorization.
13. User selects a repository.
14. Existing repository indexing and intelligence services are used.

### Security requirements

- Use OAuth state validation.
- Request only the minimum necessary GitHub scopes.
- Use the backend to exchange OAuth authorization codes.
- Never expose the GitHub OAuth client secret.
- Never expose GitHub access tokens to React.
- Use secure HTTP-only session cookies where supported.
- Apply appropriate CSRF protections.
- Handle expired or revoked authorization.
- Handle organization authorization restrictions.
- Do not store sensitive credentials in localStorage.

### Important backend compatibility requirement

The existing Increment 2 may use GitHub App installation tokens.

Inspect the current GitHub integration before modifying it.

If required, introduce or adapt a GitHub API authentication abstraction so repository operations can use OAuth access tokens.

Preserve the existing:
- Repository indexing services.
- Source extraction services.
- Code Knowledge Graph.
- PR analysis logic.
- PostgreSQL persistence.
- Graph RAG and hybrid retrieval.
- LangGraph workflows.

Do not rewrite these completed features just to change authentication.

### Repository permissions

The user must authorize appropriate repository access.

Private repositories should only be accessible when the user's authorization and organization policies permit it.

Do not assume OAuth sign-in automatically grants access to every repository.
