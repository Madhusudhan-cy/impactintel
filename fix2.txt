# Complete Frontend Redesign — ImpactIntel
## Developer Intelligence Dashboard | Aqua Green + Light Blue

### Project Objective

Redesign the existing frontend of **ImpactIntel — Repository Impact Intelligence System** into a professional developer intelligence platform.

There are TWO required changes:

1. Completely redesign the existing application UI using the Developer Intelligence Dashboard design direction and an Aqua Green + Light Blue color palette.
2. Remove the entire bottom repository preview section from the landing/index page, as previously discussed.

Implement both changes in the existing project. Do not create a new project or remove existing application functionality.

---

# PART 1 — NEW DESIGN SYSTEM

## 1. Visual Identity

Use a combination of Aqua Green and Light Blue.

### Color palette

| Purpose | Color |
|---|---|
| Main background | `#F5FAFA` |
| Card background | `#FFFFFF` |
| Primary aqua green | `#16B89A` |
| Deep aqua green | `#087F70` |
| Soft aqua green | `#DDF7EF` |
| Primary light blue | `#55BDEB` |
| Deep light blue | `#258FC7` |
| Soft light blue | `#E2F4FC` |
| Main text | `#172B35` |
| Secondary text | `#6B818B` |
| Borders | `#E1ECEE` |

### Design principles

- Use aqua green for primary buttons, active navigation, and important status indicators.
- Use light blue for graph-related elements, secondary actions, and information highlights.
- Use white surfaces with subtle borders.
- Maintain clear typography and consistent spacing.
- Use minimal shadows and restrained corner radii.
- Avoid oversized cards, excessive gradients, decorative elements, and unnecessary empty space.
- Maintain a professional engineering-tool appearance.

The result should look like a modern developer SaaS platform inspired by Linear and GitHub.

# PART 3 — REMOVE THE LANDING PAGE REPOSITORY PREVIEW

## 4. Complete Removal of the Bottom Preview Section

On the landing/index page, completely remove the repository preview panel shown below the hero section.

The section contains:

1. The repository preview header: `repo-impact-intelligence :: shop-repo`.
2. The indexed status indicator: `42 Nodes • 52 Edges Indexed`.
3. The PR Blast Radius card showing `3 Hops Transitive`.
4. The Knowledge Graph card showing `NetworkX + AST`.
5. The Floating AI Assistant card showing `Prathiksha`.
6. The entire outer preview container.
7. Its background, border, shadow, decorative elements, and related styling.

### Important layout requirements

- Remove the entire preview section from the landing page JSX.
- Remove the empty vertical space left behind.
- Adjust hero section spacing so the page looks balanced without the preview.
- Do not replace the removed section with another illustration, dashboard preview, or placeholder.
- Do not leave an empty container.

### Preserve these landing page elements

- Project logo and top navigation.
- Main heading: "Know the exact impact of every code change before you merge."
- Existing description.
- Continue with GitHub button.
- Explore Repositories button.

### Critical functionality protection

Remove only the landing page preview.

Do NOT delete:
- Actual PR impact analysis.
- Code Knowledge Graph functionality.
- Graph indexing.
- Repository indexing.
- Prathiksha chatbot.
- Shared components used on other pages.
- Backend services or API integrations.

The repository preview panel must not reappear on the landing page after the redesign.

# PART 4 — DEVELOPER INTELLIGENCE DASHBOARD

## 5. Repository Overview

Redesign the dashboard to prioritize real engineering information.

### Repository heading

Display:

- Repository owner and name.
- Current indexed branch.
- Indexing status.
- Indexed commit information.
- Inspect PRs action.
- Ask AI action.

Use a compact heading area rather than an oversized hero card.

### Repository metrics

Display four compact metrics in a horizontal row:

1. Graph Nodes.
2. Graph Edges.
3. PR Analyses.
4. Indexed Commit.

Requirements:

- Large, readable metric values.
- Small descriptive labels.
- Aqua green and light blue accent icons.
- Consistent sizing and spacing.
- Real backend data only.

Do not hardcode example values.

### Code Knowledge Graph Entities Breakdown

Show the actual counts of:

- Files.
- Functions.
- Classes.
- Components.
- Tests.
- Other supported entity types.

Provide a link to open the full Graph Explorer.

Use subtle aqua green and light blue visual indicators.

### Recent Pull Request Impact Reports

Display recent PR analyses in a clean table or compact list.

Include:

- PR number and title.
- Author.
- Changed files.
- Affected components.
- Analysis status.
- Analysis date.
- View report action.

Use actual backend responses.

Status indicators may include:
- Completed.
- Processing.
- Failed.
- Not analyzed.

Never claim tests passed unless they were actually executed.

### Repository Activity

Where supported by existing backend data, display:

- Recent indexing activity.
- Recent repository updates.
- Recent impact analyses.
- Last indexed commit.
- Indexing status.

Do not fabricate activity information.

# PART 5 — KNOWLEDGE GRAPH EXPLORER

## 6. Technical Graph Interface

Make the graph explorer look like a professional code intelligence workspace.

Use React Flow.

Requirements:

- Aqua green and light blue node styling.
- Differentiate files, functions, classes, components, API routes, and tests.
- Differentiate relationship types.
- Provide node search.
- Provide relationship filters.
- Provide node details in a side panel.
- Support expand/collapse.
- Support on-demand graph loading.
- Display dependency paths and evidence.
- Support PR-specific impact graph views.

### Graph performance

Never load the entire repository graph into React Flow by default.

Use:

- Backend-driven subgraph retrieval.
- Lazy expansion.
- Search and filtering.
- Depth limits.
- Focused graph views.

Preserve existing graph APIs and functionality.

The backend Code Knowledge Graph remains the source of truth. React Flow is only its visualization.

# PART 6 — PULL REQUEST IMPACT REPORT

## 7. PR Analysis Workspace

Redesign the PR impact report as a technical analysis workspace.

Display:

- PR metadata and summary.
- Changed files.
- Directly affected components.
- Indirectly affected components.

# PART 11 — IMPLEMENTATION PROCESS

## 12. Required Workflow

Follow this sequence:

1. Inspect the existing frontend folder structure.
2. Inspect `LandingPage.jsx` and identify the repository preview section.
3. Remove that entire preview section and its unused styling.
4. Inspect the existing layout, sidebar, header, and reusable components.
5. Establish the Aqua Green + Light Blue design tokens.
6. Redesign the sidebar and top navigation.
7. Redesign the repository dashboard.
8. Redesign the Pull Request pages.
9. Redesign the Knowledge Graph Explorer.
10. Redesign indexing, history, and settings pages.
11. Integrate the floating Prathiksha assistant.
12. Verify responsive behavior.
13. Run existing frontend tests.
14. Run the production build.
15. Fix any regressions introduced by the redesign.

Before creating new components, check whether existing components can be reused or improved.

Clean up unused imports, styles, and components only when they are genuinely no longer needed.

Do not delete shared components used by other pages.
